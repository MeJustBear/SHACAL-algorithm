# Санитайзеры: ASan + UBSan

Документ описывает, **как устроена и как запускается** санитайзер-конфигурация
сборки проекта **shacal**, и фиксирует **результат первого запуска** тестов под
ней. Это пункт 3 Этапа 4 из [`roadmap.md`](roadmap.md): прогнать тесты под
ASan/UBSan, чтобы вычистить остатки UB из унаследованного кода.

---

## Что это и зачем

**Санитайзеры** - это инструментирование кода компилятором, которое во время
выполнения ловит ошибки, незаметные при обычном прогоне (тесты могут «зеленеть»,
а память при этом тихо повреждаться). Включаются они флагами компиляции/линковки
и заметно замедляют программу - поэтому это **отдельная сборочная конфигурация**,
а не режим по умолчанию.

В проекте задействованы два санитайзера:

| Санитайзер | Флаг | Что ловит |
|------------|------|-----------|
| **AddressSanitizer (ASan)** | `-fsanitize=address` | выход за границы буфера (heap/stack/global), use-after-free, use-after-return, двойное освобождение, утечки памяти (LeakSanitizer) |
| **UndefinedBehaviorSanitizer (UBSan)** | `-fsanitize=undefined` | сдвиги на недопустимое число бит, знаковое переполнение, разыменование `nullptr`, невыровненный доступ, выход enum/bool за диапазон, неопределённое приведение и т.п. |

Почему это важно именно здесь: ядро выросло из учебного кода с известными
техдолгами (см. раздел 0 в roadmap) - ручная побайтовая сборка `uint32_t`,
циклические сдвиги (потенциальный UB при сдвиге на 0/32), арифметика по модулю
2³², ранее существовавшие утечки (`new vector` + `delete &result`). Санитайзеры
дают объективное подтверждение, что после рефакторинга Этапа 3 этих проблем не
осталось.

---

## Как это подключено

Конфигурация управляется опцией CMake `SHACAL_SANITIZE` (по умолчанию `OFF`).
При `-DSHACAL_SANITIZE=ON` флаги добавляются **ко всем целям** - ядру (`shacal_core`),
io, CLI и тестам, - чтобы инструментирование покрывало весь исполняемый код, а не
только тесты. Соответствующий фрагмент верхнего `CMakeLists.txt`:

```cmake
if(SHACAL_SANITIZE)
    if(MSVC)
        message(WARNING "SHACAL_SANITIZE поддержан только для GCC/Clang; на MSVC игнорируется")
    else()
        add_compile_options(-fsanitize=address,undefined -fno-omit-frame-pointer -g)
        add_link_options(-fsanitize=address,undefined)
    endif()
endif()
```

Пояснения к флагам:

- `-fsanitize=address,undefined` - включает оба санитайзера сразу (они совместимы);
- `-fno-omit-frame-pointer` - сохраняет фрейм-поинтер, чтобы стек-трейсы ошибок
  были читаемыми;
- `-g` - отладочная информация для номеров строк в отчётах санитайзера.

ASan и UBSan поддержаны в GCC и Clang; на MSVC встроенного UBSan нет, поэтому
там опция игнорируется с предупреждением (на Windows код проверяется обычной
сборкой, а санитайзеры гоняются в CI на Linux).

## Как запустить

Отдельный каталог сборки, чтобы не смешивать с обычной конфигурацией:

```bash
cmake -S . -B build-asan -DSHACAL_SANITIZE=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build-asan -j

# Прогон всех тестов через CTest
ctest --test-dir build-asan --output-on-failure

# Либо напрямую бинарник тестов (для сводки Catch2)
./build-asan/tests/shacal_tests
```

Полезные переменные окружения при отладке:

```bash
# Включить детектор утечек и читаемые стек-трейсы UBSan, падать на первой ошибке
ASAN_OPTIONS=detect_leaks=1 \
UBSAN_OPTIONS=print_stacktrace=1:halt_on_error=1 \
ctest --test-dir build-asan --output-on-failure
```

Если санитайзер находит проблему, он печатает отчёт (тип ошибки, адрес,
стек-трейс) и процесс завершается с ненулевым кодом - CTest помечает тест как
проваленный.

## Результат первого запуска

**Окружение:**

| Параметр | Значение |
|----------|----------|
| Дата | 2026-06-20 |
| ОС | Linux 6.8.0-117-generic x86_64 (Ubuntu 24.04) |
| Компилятор | g++ (Ubuntu 13.3.0) 13.3.0 |
| CMake | 3.28.3 |
| Конфигурация | `-DSHACAL_SANITIZE=ON -DCMAKE_BUILD_TYPE=Debug` |

**Сборка:** прошла без предупреждений (`-Wall -Wextra -Wpedantic`) и без ошибок.

**Прогон тестов под ASan/UBSan:**

```text
$ ASAN_OPTIONS=detect_leaks=1 UBSAN_OPTIONS=print_stacktrace=1:halt_on_error=1 \
  ctest --test-dir build-asan --output-on-failure
...
100% tests passed, 0 tests failed out of 20

Total Test time (real) =   0.65 sec

$ ./build-asan/tests/shacal_tests
===============================================================================
All tests passed (1271 assertions in 20 test cases)
```

**Итог:**

- все **20** тест-кейсов (**1271** проверка) прошли под ASan + UBSan;
- санитайзеры **не выдали ни одной диагностики** - ни ошибок памяти (ASan/LSan),
  ни неопределённого поведения (UBSan);
- то есть остатков UB и утечек из унаследованного кода в покрытых тестами путях
  ядра/CLI **не обнаружено**.

Это и есть требуемый Этапом 4 результат: тесты проходят под санитайзерами,
поведение алгоритма зафиксировано тест-векторами, можно безопасно двигаться к
C-ABI (Этап 5).
