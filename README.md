# shacal - блочный шифр SHACAL-1 (CLI)

[![Build and Test](https://github.com/MeJustBear/SHACAL-algorithm/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/MeJustBear/SHACAL-algorithm/actions/workflows/ci.yml)

Учебно-исследовательская реализация блочного шифра **SHACAL-1** (блок 160 бит,
ключ 512 бит) в четырёх режимах сцепления: **ECB, CBC, CFB, OFB**.

Проект в первую очередь **исследовательский**: он позволяет варьировать
параметры алгоритма (прежде всего набор раундовых констант) и оценивать их
влияние на статистические свойства и криптостойкость. 

> ⚠️ **Предупреждение.** SHACAL-1 - учебный/исторический шифр и **не является**
> современным криптографическим стандартом. Для продакшн-криптографии
> используйте AES или ChaCha20 (например, из библиотеки `cryptography`).
> Самодельная генерация ключей здесь криптографически непригодна.

---

## Сборка

Нужны CMake ≥ 3.16 и компилятор с поддержкой C++17 (GCC, Clang или MSVC).

```bash
cmake -B build
cmake --build build
```

В результате появляется единственный бинарник `build/shacal_cli`. Смена режима,
направления (шифрование/расшифрование) и типа данных выполняется **флагами
запуска** - пересборка не требуется.

---

## Тесты

Тесты ядра написаны на [Catch2](https://github.com/catchorg/Catch2) (подтягивается
через CMake `FetchContent` при конфигурации) и запускаются через CTest:

```bash
cmake -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Покрытие: be32-конверсия, циклический сдвиг, key schedule, round-trip блока,
golden-векторы (`tests/vectors/`), дополнение PKCS#7 и его валидация, round-trip
всех режимов на длинах `0..2·BLOCK` (включая невыровненные), сверка выхода CLI с
эталоном. Сборку тестов можно отключить флагом `-DSHACAL_BUILD_TESTS=OFF`.

Отдельная конфигурация с санитайзерами (`-DSHACAL_SANITIZE=ON`, ASan + UBSan)
и результат первого прогона описаны в [`docs/sanitizers.md`](docs/sanitizers.md).

## Быстрый старт

```bash
cd build

# 1. Сгенерировать ключ и вектор инициализации
./shacal_cli keygen --out key.txt
./shacal_cli ivgen  --out iv.txt

# 2. Зашифровать файл в режиме CBC
./shacal_cli encrypt --mode cbc --key key.txt --iv iv.txt -i secret.txt -o secret.enc

# 3. Расшифровать обратно
./shacal_cli decrypt --mode cbc --key key.txt --iv iv.txt -i secret.enc -o secret.out
```

Режим ECB не использует вектор инициализации, поэтому флаг `--iv` для него не нужен:

```bash
./shacal_cli encrypt --mode ecb --key key.txt -i secret.txt -o secret.enc
./shacal_cli decrypt --mode ecb --key key.txt -i secret.enc -o secret.out
```

## Команды

| Команда   | Назначение                                              |
|-----------|---------------------------------------------------------|
| `encrypt` | Зашифровать входной файл                                |
| `decrypt` | Расшифровать входной файл                               |
| `keygen`  | Сгенерировать файл ключа (16 × `uint32_t`)              |
| `ivgen`   | Сгенерировать файл вектора инициализации (5 × `uint32_t`)|

Справку можно вывести в любой момент: `./shacal_cli --help`.

---

## Аргументы

| Аргумент                       | Команды                | Обязательный | Пояснение |
|--------------------------------|------------------------|--------------|-----------|
| `--mode <ecb\|cbc\|cfb\|ofb>`  | `encrypt`, `decrypt`   | нет (по умолчанию `ecb`) | Режим сцепления блоков. Выбирается в рантайме. При расшифровании должен совпадать с тем, что использовался при шифровании. |
| `--key <file>`                 | `encrypt`, `decrypt`   | да           | Файл ключа: 16 шестнадцатеричных значений `uint32_t` через пробел (см. [Форматы файлов](#форматы-файлов)). |
| `--iv <file>`                  | `encrypt`, `decrypt`   | да для `cbc`/`cfb`/`ofb`, не нужен для `ecb` | Файл вектора инициализации: 5 шестнадцатеричных значений `uint32_t`. Тот же IV нужен при расшифровании. |
| `-i`, `--in <file>`            | `encrypt`, `decrypt`   | да           | Входной файл. |
| `-o`, `--out <file>`           | все                    | да           | Выходной файл (для `keygen`/`ivgen` - файл, куда записать сгенерированные значения). |
| `--round-consts C0,C1,C2,C3`   | `encrypt`, `decrypt`   | нет          | Четыре раундовые константы в hex через запятую (см. [Раундовые константы](#раундовые-константы)). |
| `--round-consts-file <file>`   | `encrypt`, `decrypt`   | нет          | Файл с четырьмя hex-константами через пробел. Совместим со старым `consts.txt`. |
| `--preserve-bmp-header`        | `encrypt`, `decrypt`   | нет          | Сохранять 54-байтный заголовок BMP «видимым»: он копируется без изменений, шифруются только данные изображения. |
| `--stats`                      | `encrypt`              | нет          | Вывести в консоль метрики (дисперсию битов и корреляцию вход/выход) - для исследования статистических свойств. |
| `-h`, `--help`                 | -                      | нет          | Показать справку. |

`--round-consts` и `--round-consts-file` **взаимоисключающие**: одновременно
указывать нельзя.

## Режимы

| Режим | Расшифровка                | IV   | Особенности |
|-------|----------------------------|------|-------------|
| `ecb` | Electronic Codebook        | нет  | Каждый блок шифруется независимо. Простейший, но одинаковые блоки дают одинаковый шифртекст. |
| `cbc` | Cipher Block Chaining      | да   | Блок XOR-ится с предыдущим шифрблоком перед шифрованием. |
| `cfb` | Cipher Feedback            | да   | Поточный режим на основе обратной связи по шифртексту. |
| `ofb` | Output Feedback            | да   | Поточный режим на основе обратной связи по гамме (ключевому потоку). |

## Раундовые константы

Набор из **четырёх** раундовых констant (по одной на каждый диапазон из 20
раундов из 80, как в SHA-1) напрямую влияет на криптостойкость алгоритма.
Возможность их менять - суть исследовательского проекта.

Порядок выбора констант:

1. `--round-consts C0,C1,C2,C3` - задать прямо в командной строке;
2. `--round-consts-file <file>` - прочитать из файла;
3. если ничего не указано - используются **встроенные дефолты SHACAL-1**:
   `0x5A827999, 0x6ED9EBA1, 0x8F1BBCDC, 0xCA62C1D6`.

Пример с пользовательскими константами:

```bash
./shacal_cli encrypt --mode cbc --key key.txt --iv iv.txt \
  --round-consts 0x11111111,0x22222222,0x33333333,0x44444444 \
  -i secret.txt -o secret.enc

./shacal_cli decrypt --mode cbc --key key.txt --iv iv.txt \
  --round-consts 0x11111111,0x22222222,0x33333333,0x44444444 \
  -i secret.enc -o secret.out
```

> При расшифровании набор констант **обязан совпадать** с использованным при
> шифровании, иначе на выходе будет мусор (или ошибка). Шифр не хранит константы
> внутри шифртекста - фиксировать использованный набор должен сам исследователь
> (так же, как и IV).

## Форматы файлов

Файлы ключа, IV и констант - это **текст** с шестнадцатеричными значениями,
разделёнными пробелами (формат, совместимый с прежними экспериментами):

```text
# key.txt - 16 значений
a76aefd 21fb8829 723904bb 77400a3 966cbbd5 c86ee5ed c4f9b2a9 709614d1 ...

# iv.txt - 5 значений
60e4a0dc d92a4100 e9ff1229 5a6c8c35 58fd2379

# consts-файл - 4 значения
5A827999 6ED9EBA1 8F1BBCDC CA62C1D6
```

## Работа с BMP

Без флага файл шифруется целиком как поток байт. С флагом
`--preserve-bmp-header` первые 54 байта (заголовки `BMPFILEHEADER` +
`BMPINFOHEADER`) копируются в выходной файл без изменений, а шифруются только
данные изображения - файл остаётся распознаваемым как BMP:

```bash
./shacal_cli encrypt --mode cbc --key key.txt --iv iv.txt --preserve-bmp-header -i pic.bmp -o pic.enc.bmp
./shacal_cli decrypt --mode cbc --key key.txt --iv iv.txt --preserve-bmp-header -i pic.enc.bmp -o pic.out.bmp
```

## Дополнение (padding)

Используется стандарт **PKCS#7** (RFC 5652): данные дополняются до кратности
размеру блока (20 байт) N байтами со значением N; если длина уже кратна блоку,
добавляется целый блок. При расшифровании дополнение проверяется - повреждённый
шифртекст либо неверный ключ/IV/набор раундовых констант приводят к явной ошибке
«некорректное дополнение», а не к молчаливому повреждению данных. Round-trip
корректен для входов **любой** длины.

## Архитектура

Код разделён на слои (см. [`docs/roadmap.md`](docs/roadmap.md), Этап 3):

- `src/core/` - чистое алгоритмическое ядро (`shacal1`, `padding`, `modes/`),
  работает только с буферами в памяти, без файлового I/O. Собирается в
  `libshacal_core`.
- `src/io/` - файловый/BMP-слой (`streams`, `bmp`). Собирается в `libshacal_io`.
- `src/cli/` - разбор аргументов и склейка слоёв (`shacal_cli`).

## Известные ограничения

- Генерация ключей не является криптографически стойкой - режим учебный.
